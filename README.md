# React: маршруты, состояние и кеш

Третья интерактивная лекция, продолжение книжного магазина из `React/` и `React-API/`.

[Открыть презентацию](https://ngg-dev.github.io/react-state-managers/)

Основной трек: **React Router → Redux Toolkit → RTK Query**. Дополнение: тот же магазин на **Zustand + TanStack Query**, с прежним React Router. Материал рассчитан на практический рассказ: код, действия, схемы движения данных. Тайминг ориентировочный, самостоятельной работы на занятии не требуется.

## Запуск

Требуется Node.js 22+.

```sh
npm ci
npm run check
npm run build
npm run dev
```

Открыть http://127.0.0.1:4188. Для просмотра именно `dist/`: `npm run preview` (тот же порт, сначала остановите dev).

Готовую лекцию можно открыть из `index.html` или `dist/index.html`. Сборка включает библиотеки, CDN не нужен. Демо используют настоящие React Router, Redux Toolkit/RTK Query или Zustand/TanStack Query. Сервер — явно подписанная локальная модель HTTP-ответов с задержкой, ошибкой и изменением цены; внешние запросы не отправляются. Встроенный `/api/books` не создаёт backend для студенческого проекта.

## Показ и самостоятельное чтение

- Стрелки, Page Up / Page Down — слайды; Home / End — начало и конец.
- O — оглавление, F — полный экран, Escape — закрыть оглавление.
- Внутри полей, кода, кнопок и демонстраций клавиши не переключают лекцию.
- Сценарии показа и ссылки на документацию сохранены в `src/content.js` и не выводятся на слайды.
- У схем можно выбирать шаг; у кода — подсветить строку кликом и скопировать фрагмент.
- «Сбросить демо» возвращает начальные данные. Каждый слайд имеет независимое демо; возврат к слайду также сбрасывает его. Пользовательские маршруты внутри демо изолированы через MemoryRouter, URL самой презентации указывает на слайд.

Начните с `#already-have` («Что у нас уже есть»): знакомый каталог загружает книги и изменяет общий счётчик через callback. Далее `#shop-brief` формулирует четыре задачи, `#three-tasks` показывает целевой магазин. Перед каждым инструментом есть слайд-вопрос и короткая подводка о его назначении.

В `#state-owner` видна цепочка props от App через посредников. Она объясняет неудобства роста дерева, а не объявляет useState неправильным. Redux вводится как способ организовать общий доступ и правила изменений. Порядок разбора: `#store` → `#provider` → `#cart-slice` → `#dispatch` → `#selector` → итоговая схема `#redux-flow`. Сначала показываем подключение cartReducer к store, затем раскрываем его реализацию; для запуска нужны оба файла. В конце блоков отмечаем, какая из исходных задач уже решена.

Рядом с ключевыми фрагментами кода расположены пошаговые схемы. Нажатие на узел показывает объяснение и подсвечивает связанные строки. Схемы подключения отдельно объясняют, что создаётся один раз; схемы запросов показывают событие запуска, ответ, кеш и отображение. «Пояснения к коду» раскрывают дополнительные подсказки.

Практический показ: `#routing-demo` → `#local-reset` → `#store-demo` → `#duplicate-requests` → `#cache-demo` → `#price-demo` → `#full-demo`. Альтернатива: `#alternative-demo`. `local-reset` — намеренно неудачная попытка поместить счётчик внутрь страницы; поднятый к постоянному родителю useState по-прежнему работает.

При коротком занятии store, Provider и подключение API показываем как рецепты настройки, выполняемые один раз. Основное внимание — пользовательским действиям, потоку данных и результату. Дополнение на Zustand + TanStack Query необязательно. Ориентировочный полный разбор основной части — 104 минуты, дополнение — 15; число слайдов увеличено за счёт отдельных коротких вопросов и подводок.

Задание и критерии оценивания не входят в презентацию. Для отдельной выдачи подготовлены `output/pdf/Лабораторная работа 6.pdf` и `output/lab-api.zip`. PDF состоит из трёх страниц; исходный Markdown остаётся материалом для редактирования. Готовый API не требует от студентов писать backend.

## Публикация на GitHub Pages

Репозиторий: [ngg-dev/react-state-managers](https://github.com/ngg-dev/react-state-managers). В Settings → Pages используется **GitHub Actions**. Workflow `.github/workflows/pages.yml` проверяет проект, собирает и публикует `dist/` при push в `main`; предусмотрен ручной запуск workflow.

Если публикуете без Actions: выполните `npm run build` и разместите содержимое `dist/` на статическом хостинге. Все пути относительные; имя репозитория в коде не задано. Презентация использует hash-адреса слайдов, поэтому прямые ссылки работают в подпапке Pages.

Сгенерированные `app.js`, `dist/` и временные файлы не хранятся в Git: workflow собирает презентацию из исходников. PDF лабораторной и архив API находятся отдельно в `output/` и не попадают на слайды.

## Содержание проекта

- `src/content.js` — слайды, ориентиры времени, пояснения, ссылки.
- `src/main.jsx` — React-оболочка, код, схемы и оглавление.
- `src/code-flows.js` — шаги схем и привязки подсветки к строкам примеров.
- `src/Demos.jsx` — работающие учебные магазины и сравнение запросов.
- `src/model.js` — корзина, локальная модель API, RTK Query и store.
- `styles.css` — оформление в стиле предыдущей лекции, адаптация к узкому экрану и reduced motion.
- `scripts/check.mjs` — структура лекции, компиляция JSX и проверки поведения store/кеша/изменений/ошибок.
- `Лабораторная работа 6.md` — редактируемый исходник задания; итоговый документ выдаётся отдельным PDF.
- `scripts/create-lab-pdf.py` — генератор PDF с критериями и порядком сдачи.
- `lab-api/` — готовый HTTP-сервер для лабораторной без серверных зависимостей: `node lab-api/server.mjs`, порт 4191. Позволяет проверить PATCH → GET с сохранением данных и не требует писать backend. Выдаётся отдельным архивом; сам сервер работает локально. В `dist/` входят только материалы презентации.

Фрагменты кода на слайдах подписаны именами файлов; сокращения объясняются в разборе. Основные примеры используют JavaScript. Отдельного готового проекта для сдачи лабораторной нет: студент дорабатывает свою предыдущую работу.
