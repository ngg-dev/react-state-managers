# Учебный HTTP API для лабораторной №6

Готовый сервер позволяет выполнить работу на React, даже если публичное API вашего проекта не сохраняет изменения. Сервер уже написан: ваша задача — подключить маршруты, Redux и RTK Query в **своём** React-приложении.

## Запуск

Нужен Node.js 22 или новее. Скопируйте папку `lab-api` целиком в корень своего проекта. Устанавливать серверные зависимости не нужно.

Из корня проекта выполните:

```sh
node lab-api/server.mjs
```

Оставьте этот терминал открытым. React-приложение запустите в другом терминале привычной командой, например `npm run dev`. Остановка сервера — `Ctrl+C`.

Сервер доступен только на вашем компьютере по адресу `http://127.0.0.1:4191`. CORS уже разрешает запросы из браузерного приложения. Для защиты достаточно локального запуска; этот сервер не размещается на GitHub Pages.

В существующем `createApi` укажите адрес:

```js
baseQuery: fetchBaseQuery({
  baseUrl: 'http://127.0.0.1:4191/api/'
}),
```

Далее используются endpoints из лекции: `books` и `books/` + `id`. Подключение reducer, middleware, query-хуков и mutation выполняете самостоятельно.

## Данные и запросы

Перед запуском можно заменить содержимое `books.json` сущностями своей темы: измените названия, авторов и цены, добавьте поля для ваших карточек. Сохраните уникальный `id` и числовое поле `price`. Для этого учебного сервера адрес `/api/books` и обёртки `books`/`book` остаются прежними — тема интерфейса может быть другой. После правки файла перезапустите сервер.

| Запрос | Ответ |
|---|---|
| `GET /api/books` | `{ "books": [...] }` |
| `GET /api/books/b-101` | `{ "book": { "id": "b-101", ... } }` |
| `PATCH /api/books/b-101` с JSON `{ "price": 790 }` | `{ "book": { ... , "price": 790 } }` |
| GET или PATCH неизвестного id | `404` и `{ "message": "Книга не найдена" }` |
| PATCH с пустой, отрицательной или нечисловой ценой | `400` и сообщение об ошибке |

PATCH **сохраняет новую цену в памяти**: последующий GET списка и деталей возвращает её. Перезапуск или команда сброса восстанавливает цены из `books.json`; сам файл сервер не меняет. База данных не нужна.

Проверка вручную в другом терминале:

```sh
curl http://127.0.0.1:4191/api/books
curl -X PATCH http://127.0.0.1:4191/api/books/b-101 -H 'Content-Type: application/json' -d '{"price":790}'
curl http://127.0.0.1:4191/api/books/b-101
```

В Windows PowerShell используйте `curl.exe` вместо `curl`.

## Показать пустой список

Выполните:

```sh
curl -X POST http://127.0.0.1:4191/__lab/empty
```

Затем нажмите «Обновить» в вашем React-приложении, чтобы вызвать `refetch()`. Следующий GET списка вернёт `200` и `{ "books": [] }`. Данные книг не удалены, детали по id остаются доступны. Пустой режим действует, пока вы не восстановите список:

```sh
curl -X POST http://127.0.0.1:4191/__lab/restore
```

Снова обновите запрос в приложении. Изменённые цены при этом сохранятся.

## Показать ошибку и повтор

```sh
curl -X POST http://127.0.0.1:4191/__lab/fail-next-get
```

Теперь **следующий GET списка или деталей** вернёт `500`, а следующий за ним снова будет обычным. Команда сама GET не отправляет. Нажмите «Обновить» в приложении, покажите сообщение об ошибке, затем повторите запрос. После успешной начальной загрузки прежние данные должны оставаться видны при ошибке фонового обновления.

Чтобы проверить ошибку **первой** загрузки, выполните команду и обновите страницу React-приложения: кеш в памяти исчезнет. На этот момент приложение должно отправлять один начальный GET, иначе ошибку может получить другой параллельный запрос. Не открывайте API вручную между командой и действием в приложении: такой GET использует подготовленную ошибку.

Для проверки ошибки **сохранения** остановите сервер клавишами `Ctrl+C` и отправьте корректную цену из формы. Покажите сообщение об ошибке, запустите сервер снова и повторите сохранение. Перезапуск восстановит первоначальные данные, но повторная mutation сохранит отправленную цену.

Чтобы сделать ожидание заметным, включите ограничение скорости во вкладке Network браузера. В этом API запросы настоящие, поэтому URL, статус и JSON-ответ видны в Network.

## Начать проверку заново

```sh
curl -X POST http://127.0.0.1:4191/__lab/reset
```

Сброс восстанавливает начальные цены, обычный список и отменяет подготовленную ошибку. Он не очищает Redux/RTK Query в браузере: после команды обновите страницу приложения или явно повторите запросы.
